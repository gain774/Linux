Latitude 5320 サーバー化計画

Dell Latitude 5320 を初期化して Ubuntu Server にし、FiveM ゲームサーバーと「どこからでも使える Claude Code 環境」を同居させるまでの作業手順。上から順に、チェックを付けながら進められます（進捗はこの端末に保存されます）。

Dell Latitude 5320 Core i7-1185G7 · 4C/8T RAM 16GB SSD 256GB（旧ドライブに換装） Ubuntu Server 24.04 LTS

ハード評価

この用途なら十分です。ローカル〜少人数の FiveM（目安〜16人程度）＋ Claude Code の同時運用は快適。大人数・大量 MOD になると 4 コアが頭打ちになります。256GB は OS＋FiveM（実測 20〜40GB 程度）で問題なし。ノートPCなのでバッテリーが簡易 UPS 代わりになり、常時稼働にも向きます。

この構成でできること / 制約

  • SSH・Claude Code: 外出先を含めどこからでも接続可（Cloudflare 経由、ルーターのポート開放は不要）。
  • FiveM: 友人を招くにはルーターで 30120 TCP/UDP のポート開放が必須。Cloudflare の無料プランはゲームの UDP を中継しません。
  • 24時間稼働: フタを閉じても止まらない設定 ＋ 停電復帰後の自動起動（BIOS）を入れます。
  • 2TB ドライブ: 抜いて新 PC に転用（そちらでフォーマット）。バックアップは取らない方針（本人決定・2026-08-31）。

    データ方針: バックアップは取らない（本人決定）。2TB・256GB とも全消し。卒業設計・LINE 履歴を含め復元不可。この手順書 URL と Cloudflare / Cfx.re のログイン情報だけはスマホ等、ノート外に控える（換装後は今の Windows 環境が消えるため）。
    1

    インストール USB を作る

    手を動かす今の Windows で
    1. ubuntu.com/download/server から Ubuntu Server 24.04 LTS の ISO（24.04.x 最新ポイントリリース、約 3GB）をダウンロード。
    2. balenaEtcher または Rufus をインストール。
    3. USB メモリを挿し、ISO を選択して書き込み（Rufus は既定設定のまま「スタート」→ ISO モード）。
    ISO のチェックサム（SHA256）をダウンロードページの値と照合しておくと安心です。
    2

    SSD を換装する

    手を動かす物理・要注意
    1. シャットダウン → AC アダプタと周辺機器を全部外す。
    2. 裏蓋のネジ（Latitude 5320 は 8 本前後、内 2 本は蓋に残る「キャプティブ」）を緩めて開ける。
    3. バッテリーコネクタを外す（作業中の通電防止）。
    4. M.2 SSD の固定ネジを外し、2TB (WD_BLACK SN7100) を抜く → 静電気防止袋に入れて新 PC 用に保管（中身は新 PC 側でフォーマット）。
    5. 元の 256GB SSD を挿し、ネジ止め。
    6. バッテリーコネクタを戻す → 裏蓋を閉める。
    静電気対策: 金属部に触れて放電してから作業。基板の端子には触れない。バックアップ用 USB は挿しっぱなしにしない。
    3

    BIOS を設定する

    手を動かす

    電源を入れてすぐ F2 を連打して BIOS へ。以下を変更:

    項目設定目的
    Power → AC Behavior / AC RecoveryPower On停電から復帰したら自動で起動
    Power → Block Sleep有効（任意）スリープ抑止の保険
    Boot SequenceUSB を最優先 or その場だけ F12インストーラ起動
    Secure Boot有効のままで可Ubuntu は署名済みで起動可能

    保存して終了（F10）。USB を挿したまま再起動し、F12 でブートメニュー → USB デバイスを選択。

    4

    Ubuntu Server をインストール

    画面の指示に沿ってディスク全消し
    • 言語・キーボード: 日本語 / Japanese。
    • ネットワーク: 有線なら自動で IP 取得。後で固定するのでここはそのまま。
    • ストレージ: Use an entire disk → 256GB SSD を選択 → LVM は既定のままで可。この時点で 256GB の中身は消えます（了承済み）。
    • プロファイル: 名前 / サーバー名（例 gameserver）/ ユーザー名（例 ks）/ パスワード。
    • 「Install OpenSSH server」に必ずチェック。
    • Featured snaps: 何も選ばない。

    完了したら USB を抜いて再起動。ログインプロンプトが出れば成功。IP アドレスを確認しておく:

    server console
    ip -4 addr show scope global | grep inet

    SSH で操作

    別の PC から SSH 接続（Windows なら PowerShell や Windows Terminal で）:

    your laptop
    ssh ks@192.168.x.x

    更新とタイムゾーン

    server
    sudo apt update && sudo apt full-upgrade -y

sudo dpkg-reconfigure -plow unattended-upgrades   # 自動セキュリティ更新を有効化

    SSH 鍵ログイン（推奨）

    手元の端末で鍵が無ければ作成 → サーバーへ登録:

    your laptop
    # 鍵が無ければ

    鍵で入れることを確認したら、パスワード認証を無効化:

    server
    sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo systemctl restart ssh

    ファイアウォール

    server
    sudo ufw allow OpenSSH
sudo ufw --force enable
    ルーターの DHCP 設定で、このサーバーの MAC アドレスに固定 IP を割り当てておくと以後ラク（「DHCP 予約」）。

    フタを閉じても止まらないようにする

    SSH で操作
    server
    sudo sed -i 's/^#\?HandleLidSwitch=.*/HandleLidSwitch=ignore/' /etc/systemd/logind.conf
sudo sed -i 's/^#\?HandleLidSwitchExternalPower=.*/HandleLidSwitchExternalPower=ignore/' /etc/systemd/logind.conf
sudo systemctl restart systemd-logind

# スリープ／休止を完全に無効化
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target

    これでフタを閉じて棚に置いても稼働し続けます。バッテリーは充電しっぱなしになりますが、常時給電運用では通常問題ありません。

    7

    遠隔アクセス：Cloudflare で SSH をどこからでも

    SSH で操作ダッシュボード操作あり

    Cloudflare One / Zero Trust（無料プラン・最大50ユーザー）で実現できます。ポート開放は不要。方式は 2 つ、独自ドメインの有無で選びます。

    共通：cloudflared を入れてトンネル作成

    server
    curl -L https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main" | sudo tee /etc/apt/sources.list.d/cloudflared.list
sudo apt update && sudo apt install -y cloudflared
cloudflared tunnel login        # ブラウザで認可（URL を別端末で開く）
cloudflared tunnel create homeserver

    方式A：独自ドメインあり → Public Hostname + Access

    1. Zero Trust ダッシュ → Networks → Tunnels → homeserver → Public Hostname を追加：
      ssh.example.com / Type: SSH / URL: localhost:22。
    2. Access → Applications で ssh.example.com を「Self-hosted」アプリとして登録し、ポリシーを自分のメール（ks07shuhei26@gmail.com）のみ許可に。
    3. 手元の端末に cloudflared を入れ、~/.ssh/config に:
      your laptop · ~/.ssh/config
      Host homeserver
  HostName ssh.example.com
  User ks
  ProxyCommand cloudflared access ssh --hostname %h
    4. 以後 ssh homeserver で、外出先からでもブラウザ認証付きで接続。

    方式B：ドメインなし → WARP + Private Network

    1. Zero Trust ダッシュ → Networks → Tunnels → homeserver → Private Network にサーバーの LAN セグメント（例 192.168.1.0/24）を追加。
    2. Settings → WARP Client でデバイス登録ポリシーを作成（自分のメールのみ）。
    3. 手元の PC / スマホに Cloudflare WARP アプリを入れ、「Login with Cloudflare Zero Trust」でチーム名を入力して参加。Split Tunnel にそのセグメントを含める。
    4. WARP を ON にすれば、外出先からでもサーバーの LAN IP に直接 ssh ks@192.168.1.x で到達。

    常駐サービス化

    server
    sudo cloudflared service install
sudo systemctl enable --now cloudflared
    より手軽に済ませたい場合の代替は Tailscale（curl -fsSL https://tailscale.com/install.sh | sh）。どちらか一方でOK。

    FiveM サーバーを構築

    SSH で操作

    専用ユーザーと依存パッケージ

    server
    sudo apt install -y xz-utils libatomic1 git
sudo useradd -m -s /bin/bash fivem
sudo su - fivem

    サーバー本体（FXServer）と server-data

    artifacts ページで最新の recommended ビルドの URL をコピーして:

    server · as fivem
    mkdir -p ~/server ~/txData && cd ~/server
wget "https://runtime.fivem.net/artifacts/fivem/build_proot_linux/master/XXXX-.../fx.tar.xz"
tar xf fx.tar.xz && rm fx.tar.xz
cd ~ && git clone https://github.com/citizenfx/cfx-server-data.git server-data

    ライセンスキー

    portal.cfx.re（旧 keymaster）で無料のサーバーキーを発行。

    txAdmin で初期設定

    server · as fivem
    cd ~/server
./run.sh          # txAdmin が :40120 で起動

    ブラウザで http://<サーバーIP>:40120（外部からは Phase 7 の経路越しに）を開き、ウィザードで管理者アカウント作成 → 「server-data」フォルダとライセンスキーを指定 → 既定のレシピでデプロイ。

    systemd で常駐化

    server · /etc/systemd/system/fivem.service
    [Unit]
Description=FiveM Server (txAdmin)
After=network-online.target

[Service]
User=fivem
WorkingDirectory=/home/fivem/server
ExecStart=/home/fivem/server/run.sh
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
    server
    sudo systemctl daemon-reload
sudo systemctl enable --now fivem
sudo ufw allow 30120                 # ゲーム接続
sudo ufw allow from 192.168.0.0/16 to any port 40120   # txAdmin は LAN だけ

    FiveM を友人に公開する

    ルーター設定
    • ルーターの管理画面でポート転送を追加：外部 30120 → サーバー IP 30120、TCP と UDP の両方。
    • 自宅のグローバル IP が変動する場合は DDNS（ルーター内蔵機能 or DuckDNS）を設定。
    • 接続テスト：友人に connect <グローバルIP or DDNS名> を試してもらう。ポート開放チェッカーで 30120 を確認。
    なぜ Cloudflare 越しにできないか: FiveM のゲーム通信は UDP を使いますが、Cloudflare の無料プランは任意の UDP を中継しません（Spectrum は有料）。管理用の SSH/txAdmin は Cloudflare、ゲームポートだけルーター開放、という住み分けになります。
    CGNAT に注意: 携帯回線テザリングや一部の光回線ではグローバル IP が割り当てられずポート開放不可。その場合は playit.gg などのトンネルか、Cloudflare とは別の VPN 方式（友人も WARP/Tailscale 参加）を検討。
