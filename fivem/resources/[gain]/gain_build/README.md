## 参考にしたもの

`fivem/docs/DESIGN-PROCESS.md` の手順に沿って調べた結果:

- **Base Building（Rust/DayZ 風）** — プロップをスナップ配置する。拠点防衛が主眼で、
  間取りを設計する概念が無い
- **Builder Job** — 建設現場の作業アニメと報酬。建てても使える家にならない
- **住宅スクリプト（ps-housing 等）** — 既製シェルを出し入れするだけ。間取りは作れない

いずれも有料または方向が違う。**「図面を引く → 素材を運ぶ → 労働力を使う → 入れる家が増える」
という流れは見当たらなかったので、1から設計した。**

実測でも住宅は 62% が導入しているのに最大手で 7%。決定版が存在しない唯一のカテゴリ。

## 技術的な制約

**GTA は実行時にメッシュを作れない。** モデルは事前に `.ydr` として用意してストリームする
必要があるので、描いた形状がそのまま3Dモデルとして生まれることは原理的にない。

そこで壁は長さの部品ライブラリ（4 / 2 / 1 / 0.5 / 0.25m）から二進分解で組む。
CAD のスナップを 0.25m に合わせてあるので必ず組める。7.3m の壁なら 4+2+1+0.25 の4個。

部品の `.ydr` 化はまだ済んでいない。`fivem/tools/genkit.py` が `.obj` を生成するところまで。

## 使い方

```
/cad        図面を引く（W 壁 / D ドア / N 窓 / R 部屋 / E 削除）
/stake      読み込んだ図面を立っている場所に地縄張りする
/unstake    地縄を消す
```

## 設計

- **座標も図面もサーバーが検証する。** 壁の本数・座標の範囲・NaN・開口が壁からはみ出して
  いないか・部品数が上限を超えていないかを、保存前にすべて確認する
- 他人の図面は更新できない
