# gain_spawn

スポーンの権威。初回スポーン、位置の復元、死亡からの復帰をここに集約する。

## なぜ独立したリソースなのか

以前はスポーン処理が `gain_core/client/main.lua` にあり、同時に `basic-gamemode` も
`setAutoSpawn(true)` と `forceRespawn()` を呼んでいた。結果として、マップ既定の
spawnpoint（`fivem-map-skater` の `a_m_y_skater_01` など）に一度湧いてから
gain_core に引っ張られるという動きになっていた。見た目もスケーターになる。

さらに `setAutoSpawn(false)` で標準の自動復帰を切っている一方、死亡・復帰の処理が
どこにも無かったため、死ぬと戻れなかった。

スポーンは「誰が最後に呼んだか」で結果が変わる典型的な領域なので、権威を1箇所に置く。

## 何を参考にしたか

**該当する既存実装は無い。実質1から設計した。**

`fivem/docs/DESIGN-PROCESS.md` の手順に沿って調べた結果:

- 実測調査（1,211サーバー）でスポーン管理は独立したカテゴリとして立っていない。
  各サーバーがフレームワーク内に自作している領域
- 読めるものは `spawnmanager`（FXServer 同梱）のみ。ただし借りたのは
  「autoSpawn を切って自前で座標を置く」という制御の型だけで、コードは使っていない
- 有料品は該当なし

位置の権威・死亡復帰・ロード画面の畳み方は自分で決めた。

## 設計

- **座標はサーバーが決める。** クライアントから座標を受け取ることは一切しない。
  クライアントが送るのは「死んだ」という事実だけで、それもサーバー側で体力を確認する
- **死亡はサーバーが確定させる。** `gain_spawn:playerDied` はサーバー内イベントで、
  検証を通った死亡だけが流れる。アンチチートはクライアントの生イベント
  （`baseevents:onPlayerDied`）ではなくこちらを見る
- **詰まない。** サーバーからの指示が届かないまま `LoadTimeoutMs` を過ぎたら、
  ロード画面を畳んで既定地点に出す

## 公開しているもの

| export | 内容 |
|---|---|
| `Respawn(src)` | 復帰させる（管理コマンドの蘇生などから使う） |
| `IsDead(src)` | 死亡中か |

| イベント | 向き | 内容 |
|---|---|---|
| `gain_core:spawn` | server → client | キャラクター読み込み後の初回スポーン。gain_core が投げる |
| `gain_spawn:doSpawn` | server → client | 復帰地点へ出す |
| `gain_spawn:reportDeath` | client → server | 死亡の報告。サーバー側で裏を取る |
| `gain_spawn:playerDied` | server 内 | 検証済みの死亡。他リソース向け |

## 既知の未確認事項

`GetEntityHealth` がサーバー側で死亡時にどの値を返すか（build 35245）は実測できていない。
現状はクライアントの報告を受けてサーバー側で「明らかに生きている」場合だけ弾く作りにし、
`gain_logs` に `serverHealth` を記録している。件数が溜まったら、クライアントの報告に
頼らない死亡検知へ切り替えられる。

復帰させるだけの操作なので、報告を偽装されても得られるものが無い点は設計時に確認した。
