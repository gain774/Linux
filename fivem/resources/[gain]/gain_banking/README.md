# gain_banking

銀行窓口・ATM・送金・取引履歴。

## 参考にしたもの

**該当する決定版が無い領域。** 実測では銀行・経済カテゴリの普及率 88% に対し、
最大手の esx_addonaccount でも 22%。設計は1から起こした。

## 変えたところ

**「片方を減らして片方を増やす」をやめた。** 預入・引出は `core:MoveMoney` の1呼び出しにしてある。
両側を先に検査してから動かすので、片方だけ反映されることが原理的に起きない。

**送金の順序を厳格にした。**

1. 先に送金者から手数料込みの総額を引く（台帳に載る額が実際に引かれた額になる）
2. 入金は `core:AddMoneyOffline` に任せる。オンライン判定と実行を1箇所に寄せることで、
   「判定は offline、実行時には online」という競合の窓を消した
3. 入金に失敗したら**全額返金する**。純差分が 0 になるので照合が通る

以前はここで存在確認の `SELECT` を挟んでおり、その `await` の間に相手が接続すると
送金分が消えていた。

**履歴を自前で書かない。** 記録は `gain_core/server/ledger.lua` が1箇所で行う。
以前は成否と無関係に履歴を書いていたため、監査証跡が嘘をつく状態だった。

**明細の符号は `delta` から取る。** 種別の一覧を UI に持たせると、`kind` が増えるたびに符号が狂う。

## 制約

ATM はプロップなのでサーバーが座標を持てず、距離検証ができない。
そのため**送金は銀行窓口のみ**とし、ATM は預入・引出だけにしてある。
