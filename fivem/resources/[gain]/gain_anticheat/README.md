# gain_anticheat

サーバー側の検知と段階処分。

## 前提

**クライアント側のチートを完全に防ぐことは原理的にできない。** ここでやるのは、
サーバーが持つ値との矛盾を検知して記録し、悪質なものを追い出すところまで。

## 参考にしたもの

**該当なし。** 有料のアンチチートは名前を隠すのが普通で（実測でも導入率 19% は下限値）、
中身も見られない。サーバー側で観測できる値だけを使う方針で1から設計した。

## 変えたところ

**クライアントからの申告を信頼できる情報源にしない。**

以前は `baseevents:onPlayerDied` / `onPlayerKilled` を生の `RegisterNetEvent` で受けて
猶予を張り直していた。イベント名は公知なので、クライアントが猶予時間より短い間隔で
撃ち続けるだけで、テレポート検知と速度検知を**恒久的に無効化できた**。

いまは2つの経路で死亡を知る。

- `gain_spawn:playerDied` — サーバー側で確定させた死亡
- 巡回スレッドが見ている体力 — 0 になったら死亡、正数に戻った tick で猶予を張り直す

加えて、1分あたりの猶予付与回数に上限を置き（`maxGracePerMinute`）、超えたら `spam` として記録する。

## 運用

導入直後は `ACConfig.Mode = 'log'` のまま回し、誤検知が出ないことを確認してから
`'enforce'` に切り替える。`admin` 以上は検知対象外。
