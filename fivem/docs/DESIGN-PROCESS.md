# 作り方のルール

これから作るすべての gain_* リソースに適用する。

> **既存実装があるなら、まず調べて真似る。無いなら1から作る。**

FiveM のエコシステムには、同じ機能を解く実装が既にいくつもある。それを見ずに書き始めると、
先人が踏んだ罠を全部踏み直すことになる。逆に、調べた結果「決定版が無い」と分かるカテゴリもあり、
その場合は堂々と1から設計してよい。どちらなのかを最初に判定する。

---

## 手順

### 1. 実測データでそのカテゴリの現状を見る

`FiveM モッド実測地図`（1,211サーバーの導入リソースを実測した調査）に、19カテゴリの普及率と
実質的な勝者が載っている。販売サイトの宣伝文ではなく、稼働中のサーバーが実際に読み込んでいる
ファイル名が根拠になっている。

見るべきは2点。

- **そのカテゴリの普及率** — 62% のサーバーが入れているなら、無いと不便だということ
- **勝者が居るかどうか** — 導入率が1つに寄っていれば事実上の標準がある。散らばっていれば決定版が無い

例: 住宅は 62% が導入しているのに最大手でも 7%。需要はあるのに全員が違うものを使っている。
つまり参考にすべき実装が実質存在しないカテゴリで、ここは1から設計する側になる。

### 2. ソースが読めるものは読む

無料かつ公開されているものは、実物を読む。契約の形・データモデル・イベント設計・命名を学ぶ。

| 読めるもの | 実測導入率 |
|---|---|
| ox_lib | 88% |
| oxmysql | 94% |
| pma-voice | 87% |
| PolyZone | 70% |
| ox_target / ox_doorlock | 各 56% |
| ox_inventory | 54%（日本では 93%） |

読むときは「何を持っているか」より **「何を持たないことにしたか」** を見る。
ox_inventory がフレームワークに要求している契約が ox 系でわずか 93 行しかないのは、
残りを全部自分で抱えているからで、それ自体が設計判断の結果になっている。

### 3. 有料・暗号化されているものは、買わない・入手しない・再配布しない

プロジェクトの既定方針。公開ドキュメント、デモ動画、ユーザーの説明から **仕様だけ** を把握する。
中身は見られないし、見る必要もない。「何ができるか」が分かれば設計はできる。

### 4. コードは写さない

ox 系の多くは LGPL / GPL 系のライセンスで、コードを持ち込むとライセンス義務が伝播する。
**設計を学んで、自分で書く。**

真似てよいもの: 責務の分け方、データモデル、API の粒度、イベントの契約、命名の慣習
真似てはいけないもの: ソースコードそのもの、アセット、暗号化されたリソースの中身

参考にした実装は、そのリソースの `README.md` に記録する。

### 5. gain_* の設計原則に合わせる

既存実装をそのまま持ってくるのではなく、この枠に収まる形に翻訳する。

- 公開面は exports のみ。全部入りオブジェクトを作らない
- 状態は statebag に置き、イベントは「何かが起きた」の通知だけにする
- 金額・権限・到達判定はすべてサーバー側で計算する。クライアントから来た数値は信用しない
- 残高の変更は必ず取引履歴を伴う。履歴から残高が再現できる状態を保つ
- コアに常時ループ（`Wait(0)`）を置かない
- 1リソースは1人が全体を把握できる大きさに保つ。超えたら機能ではなく設計を疑う

### 6. 該当する既存実装が無ければ1から設計する

その場合、なぜ既存が無いのかを一度考える。需要が無いのか、技術的に難しいのか、
それとも各サーバーの事情が違いすぎて共通化できないのか。理由によって作り方が変わる。

---

## 各リソースの README に残すこと

- **何を参考にしたか** — 実装名とバージョン、あるいは「該当なし」
- **どこを変えたか** — 参考元と違う判断をした箇所
- **なぜ変えたか** — その理由。ここが後から一番効く

---

## 適用例

### gain_spawn（スポーン管理）

1. 実測: スポーン管理は独立カテゴリとして立っていない。各サーバーが自作している領域
2. 読めるもの: `spawnmanager`（FXServer 同梱）の API 設計程度
3. 有料品: 該当なし
4. 判定: **実質1から設計する**。`spawnmanager` からは「autoSpawn を切って自前で座標を置く」
   という制御の型だけを借り、位置の権威・死亡復帰・ロード画面の畳み方は自分で決める
